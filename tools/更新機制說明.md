# 自動更新機制設計(SpiritZh)

給未來的自己看的。**核心原則:GitHub 帳號被盜,也不能讓使用者裝到假的更新檔。**

## 為什麼要簽章

只驗 SHA256 是不夠的 —— 雜湊值寫在 `version.json`,而它跟 ZIP 都在同一個 GitHub 上。
帳號被盜 → 對方**兩個一起改** → 驗證照樣通過 → 使用者自動下載到惡意檔案。

加上簽章之後,偽造更新需要**私鑰**,而私鑰只在你自己的電腦上(`G:\SpiritZh_簽章金鑰\private.xml`)。

| 攻擊者做得到 | 有簽章的結果 |
|---|---|
| 改 GitHub 上的 ZIP | 雜湊對不上 → 擋下 |
| 改 ZIP + 改 version.json 的雜湊 | 簽章對不上 → 擋下 |
| 換掉 version.json.sig | 公鑰驗不過 → 擋下 |
| 偽造簽章 | 需要私鑰 → 做不到 |

**沒有簽章的自動更新,比沒有自動更新更危險。**

## 檔案角色

| 檔案 | 位置 | 公開? |
|---|---|---|
| `private.xml` | `G:\SpiritZh_簽章金鑰\`(專案外) | ❌ 絕對不可外流,弄丟要重來 |
| `tools/public_key.xml` | repo | ✅ 公開,並嵌進設定工具 |
| `version.json` | repo 根 + Release 附件 | ✅ |
| `version.json.sig` | repo 根 + Release 附件 | ✅ |

私鑰**現在就要備份**到隨身碟或私人雲端。弄丟 = 以後發不出使用者信得過的更新
(只能換新公鑰、要求所有人重新手動安裝一次)。

## version.json 格式

```json
{
  "schema": 1,
  "version": "3.76.4",
  "released": "2026-08-25",
  "notes": "https://github.com/OWNER/REPO/releases/tag/v3.76.4",
  "min_tool": "3.76.4",
  "packages": {
    "pure":  { "file": "…_一鍵安裝包_v3.76.4.zip", "url": "…", "size": 51293262, "sha256": "403A…" },
    "guild": { "file": "…_公會專用版_v3.76.4.zip", "url": "…", "size": 58596981, "sha256": "47A2…" }
  }
}
```

* `min_tool`:舊版工具低於這個版本就只提示「請手動下載」,不自動更新
  → 將來改格式時,舊工具不會誤解新格式
* **簽章是對檔案的位元組做的** → 產檔時固定 **UTF-8 無 BOM + LF**,
  之後任何工具都不可以「順手」改編碼或換行,差一個位元組就驗不過

## 設定工具端的流程

```
工具啟動(可設定關閉)
  ↓ 下載 version.json + .sig(raw.githubusercontent.com,不吃 API 速率限制)
  ↓ 用內嵌公鑰驗簽 ── 驗不過 → 靜靜放棄(不提示、不重試,避免被當成攻擊面)
  ↓ 比對版本
「發現新版 v3.76.4」[下載] [稍後] [不再提醒]
  ↓ 下載 ZIP 到暫存 → 驗 SHA256(對照已驗簽的 version.json)
「已下載完成,關閉遊戲後按安裝」[安裝] [稍後安裝]
  ↓ install.ps1(既有流程,會保留使用者設定檔)
```

**不做全自動安裝**,理由有二:

1. 安裝要覆蓋遊戲資料夾的檔案,**遊戲開著時檔案是鎖住的**,一定失敗
2. 靜默覆蓋別人的東西是壞習慣 —— 使用者應該知道自己的遊戲被動了什麼

設定:`關閉 / 只通知 / 自動下載(仍需按安裝)`,預設「只通知」。

## 發佈流程

```powershell
# 1. 打包(既有流程)
.\pack.ps1

# 2. 產生並簽署 version.json(會自我驗證一次,驗不過就不寫檔)
.\tools\sign_release.ps1 -Version 3.76.4

# 3. GitHub → Releases → tag v3.76.4 → 上傳 4 個檔
#    兩個 ZIP + version.json + version.json.sig
# 4. version.json / version.json.sig 一併 commit 進 repo 根目錄
```

## 踩過的坑

* **`.gitignore` 不支援行尾註解** —— `!tools/public_key.xml   # 說明` 會把整行(含註解)
  當成檔名樣式,規則靜靜失效。註解一定要自己一行。
* **PowerShell 5.1 讀 `.ps1` 預設當 ANSI** —— 腳本一律存成 **UTF-8 with BOM**,
  否則中文全變亂碼、還會噴解析錯誤。
* **`.gitignore` 用白名單寫法**(先 `*` 全擋,再逐項放行):這個資料夾混著開發筆記、
  網友回報(含別人的 ID)、競品分析、翻譯字典 —— 黑名單寫法遲早會手滑外流。
